ALBUM BUILDER: ADMIN SIGN-IN REQUIRED

What it does
- The Album Builder lives at  yoursite.com/api/album-builder  (short links  /album-builder  and  /tools/album-builder.html  both go there).
- Only a signed-in admin-portal user who may publish albums (Editor, Admin, Super Admin) gets the page.
- Anyone else (visitors, signed-out people, accounts without publish permission) is sent to the public albums gallery (/#gallery). They never see the editor.
- Two locks: the server only sends the page to signed-in editors (api/album-builder.js), and the page checks the sign-in again itself.
- Publishing was already protected by the sign-in (api/album.js). Nothing about that changed.

Upload steps (GitHub)
1. Unzip and upload everything to the website repository, keeping the folder names. Replace files when asked.
   (tools/album-builder.html is now only a small redirect to /api/album-builder, so there is nothing to delete.)
2. If you already have a .vercelignore file, do not replace it. Just make sure it contains this line:
       album-builder-src/
3. Commit. Vercel deploys by itself (about a minute). Hard-refresh the browser afterwards (Ctrl+Shift+R).

If an admin is still sent to the gallery
- Make sure you are signed in to the admin portal in the SAME browser, then open yoursite.com/album-builder.
- The reason is in the response header "X-Album-Gate" of the redirect (browser DevTools > Network):
    not-signed-in | no-publish-permission | auth-not-configured | error

Changing where visitors are sent
- Change PUBLIC_URL ('/#gallery') in api/album-builder.js and in album-builder-src/album-builder.html.

Editing the Album Builder page later
- The editable page is album-builder-src/album-builder.html (it is not public).
- After you edit it, run:  node album-builder-src/build.js
  That rewrites api/_lib/album-builder-page.js. Commit both files.
